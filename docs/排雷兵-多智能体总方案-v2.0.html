排雷兵：多智能体系统总体方案

生成对抗式代码审查能力训练 · 星型三平面架构
郑州大学首届 AI 智能体创新应用大赛 版本 v2.0 2026-11
一句话概括：学生不是来问 AI 答案的，是来当审查者的。系统离线造一份带确定缺陷的材料，在线用对抗方把他的判断逼到具体，最后用两级裁判给出 L0–L4 的能力等级。RAGFlow 三库为出题、对抗和裁判提供可追溯的判例参考，但不替代执行证据与最终判定。整场训练在线模型调用硬上限 12 次。

一 · 要解决的问题

AI 写代码的能力已经超过多数初学者，随之出现一个新的能力断层：学生越来越会生成，越来越不会判断生成物对不对。传统教学让学生「写对」，但没训练他「看出哪里不对」——而这恰恰是 AI 时代最稀缺的能力。

本系统把训练目标从「产出」翻转为「审查」：

  • 对手不是 AI 的正确答案，而是 AI 的典型缺陷。缺陷类型从逻辑、边界、API 误用、数据泄露、类型混淆、安全、性能到文档不一致，覆盖 8 类。
  • 评分不看「说对没」，看「说清没」。能感知到有问题只是 L1；定位到具体位置才是 L2；说清触发条件 L3；给出可执行修复 L4；指错方向则判 L0。
  • 对抗方负责追问，不负责判分。话术可以放开，判分口径锁死在封闭集里，两者物理分离。

为什么是星型，不是图

多智能体系统最常见的失败不是模型不够强，而是责任不清：谁改了状态、谁花了钱、谁做了最终判断，事后查不出来。星型结构把这三个问题一次性解决：

  • 状态只有一个写者。会话状态机在后端，agent 只能「提议」下一步，不能自己跳步。
  • 钱只有一个出口。所有在线调用必须走 Router.call()，它在发请求之前查额度，发完立刻记账。
  • 判断只有一个来源。抽取表由代码写，不是模型写；模型只能在闭集里选标签。

代价是灵活性：不能运行时动态建图。但本项目要的是可复现、可验收，不是拓扑搜索——这条取舍写在「不做的事」里。

四 · 一条主链

拆成 open / submit / settle 三段，同时服务两种用法：Web 端一场会话跨多个请求，学生一轮一轮交；评测与单测用 run() 脚本作答一口气跑完。两套走同一段代码，不存在「演示版」和「评测版」。

第一段 · 离线准备（0 次在线调用）

取出题单先按内容指纹查题库；命中则整条复用（题、证据链、diff 一起拿走），跳过出题与埋雷
出题写一份正确原文，Python 材料末尾带 # OK 健康标记
切分并索引代码按函数切、数据按表切、文章按小节切；按函数切是为了不让边界处理与签名分家
RAGFlow 召回并截断从绑定知识库召回 8–12 块；本地按雷型、关键词、相似度重排，过滤冲突雷型并跨文档 SHA256 去重，最后只留 3 段作为证据链（PREPARED_SOURCE = 3）
埋雷只改一处；改后与原版相同、或返回非法结构，直接判失败
探针复核原版必须通过、埋雷版必须失败。任一不满足 → 这道题不进本场评分
封印索引之后只允许按 evidence_id 取回；再写入或再检索直接抛错

退场有两种：复核不通过、召回为空。两者都计入 unverified_items，账面按出题单总数算，不允许静默漏记。

第二段 · 在线对抗（每题 2–3 轮）

下发给学生只发埋雷版代码、题面、轮次与证据片段；不发原版、diff、判级提示、锚点
学生作答说出问题在哪、什么输入触发、怎么改、引用了哪几段证据
对抗追问每次 1 次调用，只顶最含糊的一处；Adversary 可读取主判例库与缺陷模式库的封存参考，但不得照抄答案、位置或判级
提前收束预算余量 ≤ 3 时停止追问，把最后 3 次留给结算与复盘

第三段 · 结算（3 次）

代码写抽取表每道题一行：有没有定位、有没有触发条件、有没有修复、引了哪些证据、推导等级。单写者，模型不参与
决策档判标签只吃这张表，不吃学生原话；回 defect_present / no_defect 二值与置信度
必要时升级挑置信度最低的一道，读原文 + 封存证据 + 整段对话，并对照三库参考；全档允许判 L0。每场最多 1 次
引用核验拿学生标的 id 与封存集比对，本地算 precision / recall，不花调用
复盘只读结算表写 300 字；无题可判或调用失败时退本地模板

五 · 五条设计铁律

① 预算可强制执行

12 次不是靠自觉。所有在线调用只有 Router.call() 一个出口，它先 budget.check() 再发请求，发完立刻 record()。想多插一次调用，必须同时改 STAGE_TIER 与 STAGE_LIMITS，绕不过去。

② 切分点选在可判性上

决策档不读学生原话，只吃代码抽取的结构化表——模型对「没有缺陷」的判断天生偏，读到原话就被带跑。只有拿不准时才升级，让读原文的推理档去判。

③ 标签锁死闭集

标签只有「命中 / 未命中」两个取值，没有「部分正确」。模型输出越域条目直接丢弃，不翻译成「接近的合法标签」——翻译等于给越权开口子。丢掉的条目退回本地抽取表直判。

④ 检索一次即冻结

seal() 之后 retrieve() 抛错。在线阶段交给裁判和对抗的是 SealedView，它只有 fetch()——「再查一次」在类型层面就写不出来。

⑤ 对抗与裁判不得同源

升级裁判复核的正是对抗方参与过的对话。同一个模型既当质询者又当复核者，等于自己查自己。所以对抗是独立一档，配第二家厂商才算真隔离；只配一家也能跑，但健康检查会如实写 vendor_isolated: false——降级可以，假装做到了不行。

⑥ 坏题绝不判学生

探针复核放在封印之前。雷没埋上、或埋完之后原版也挂了，这道题本身是坏的；拿坏题判学生，学生答对了也会被判错——这是产品最不可原谅的错，宁可少一道题。

六 · 判级口径 L0–L4

等级枚举值rank含义判定来源
L0L0_false_alarm0误报：所指之处经证据核实并无该缺陷，或张冠李戴、把无关写法当雷仅升级层
L1L1_perception1感知到「有问题」，但说不出在哪闭表 / 升级层
L2L2_localization2定位到具体位置，未说明触发条件闭表 / 升级层
L3L3_attribution3定位 + 触发条件，未给修复闭表 / 升级层
L4L4_repair4定位 + 触发 + 可执行修复闭表 / 升级层
为什么 L0 只能由升级层给：抽取表只有三个命中位（定位 / 触发 / 修复），它判得了「学生停在哪一档」，判不了「他说的是不是真的」。三栏全不中可能只是没看出来（L1），不等于误报；而「张冠李戴」在表上与「没看出来」长得一模一样。误报的本质是断言了错误归因，只有看到原文与证据才判得了方向。所以闭表从 L1 起步，L0 留给读原文的升级档。

代价：纯 L1 学生置信度不低，不会触发升级，也就拿不到 L0。这个取舍是刻意的——把「没看出来」判成「误报」的伤害，远大于「误报漏判」的伤害。

七 · 数据契约

所有跨角色传递的结构都是冻结数据类，构造时自校验，非法结构在生成处就炸，不会流到下一层。

结构关键字段自校验规则

证据编号

evidence_id = "ev_" + sha256(doc_id + "\x00" + char_start + "\x00" + char_end)[:12]

编号由位置决定，不由顺序决定。同一份文档重跑一次，同一段证据还是同一个 id；这样学生的引用可以被独立复核，也让题库跨会话复用时能重新绑定。

八 · 与检索后端的对接

我方只依赖五个接口，后端可以用任何实现（当前为 RAGFlow 三库 + 题库/结构记忆等业务库）。契约写在 docs/rag-api.md。

接口语义关键约束
POST /v1/index写入一份文档幂等覆盖；入参没有「学生作答」字段；封印后必须报错
POST /v1/retrieve召回片段支持 doc_id 过滤（防止召回别的题的片段）；返回的 len(text) 必须等于区间长度；不做在线改写
GET /v1/evidence/{id}按 id 取回封印后唯一的读路径
POST /v1/seal冻结索引封印后 index / retrieve 都必须拒，双保险
GET /v1/summary健康与统计（可选）用于运维，不在关键路径

错误码口径

场景错误码责任方
状态非法（如 reserve 缺 stage）409后端持状态转移表，agent 只提议不改状态
越权检索（跨会话 / 锚点外）403后端做锚点 allowlist，越界显式拒绝而非返回空
引用越域（evidence_id 不在封印集）422后端在入口拒收，不照单全收再算分
检索降级 / 真实失败—降级返回判例；真实失败返回空，主链不断

锚点：一场训练只有一份判例集合

  • 「锚点」= 一道题在封印时刻冻结的证据集合，裁判升级与对抗质询吃同一份，不存在两套口径。
  • 对抗如需在线检索，范围限定在该题锚点闭集内取 top 块；锚点外返回即越权。
  • 锚点在封印后不可增删；要换判例集合 = 重新开局。
  • 锚点永不下发给学生：里面有触发条件、修复方案、埋雷位置，随题下发等于把雷标出来。

RAGFlow 三库绑定与实际作用

当前部署不是把所有 Agent 接到同一个库，而是按职责绑定不同知识库。三库均通过 RAGFlow API 访问，检索结果先经过本地重排、雷型冲突过滤和跨文档 SHA256 去重，再进入题目锚点；封印后只允许按 evidence_id 读取。

知识库数据集 ID主要内容接入 Agent对结论的实际影响
主判例库 ac92d450cbd711f18b868b1ef2314a80 真实缺陷案例、触发条件、定位方式与修复证据 Builder、Planter、Adversary、Judge 提供相似案例和证据锚点，帮助出题和追问落到具体触发条件；Judge 用它核对学生归因是否与已知案例一致

检索链路与可观测指标

  1. 召回：按题目、语言和显式雷型请求对应知识库；主判例库可作为候选召回源，另外两库提供针对性参考。
  2. 重排：本地综合显式雷型、关键词和相似度排序；冲突雷型直接过滤，不把错误案例交给 Agent。
  3. 去重与缓存：跨文档正文 SHA256 去重；默认查询缓存 TTL 为 300 秒，空结果不缓存，代码查询保持大小写敏感，缓存按服务、密钥指纹、查询和知识库隔离。
  4. 冻结：最终选中的参考写入锚点，在线阶段只读；Reporter 汇总请求数、召回数、选中数、平均相似度、缓存命中、过滤数、重复数和实际参考字符数。
真实联调结果：本地服务 http://localhost:8010/docs 已验证 RAGFlow connected=true。一次完整验证产生 4 次检索请求（主判例库 2 次、缺陷模式库 1 次、正确代码反例库 1 次），最终选中主判例 3 条、缺陷模式 1 条、正确反例 1 条；跨文档去重参考 5 条，过滤错误雷型 5 条，实际发送给 Agent 的参考字符数为 4090。该数据说明 RAG 已进入对抗和裁判上下文，而不是只停留在配置层。

RAG 的作用边界：检索结果是参考和证据候选，不是自动判分结果。探针的运行结果、学生引用、结构化抽取表和裁判规则仍是最终判级依据；RAGFlow 不可用时返回空或降级判例，并在报告中显式标记。

九 · 安全与防作弊

不整段喂裁判

决策档只吃结构化表。这既是精度设计（避免被学生话术带跑），也避免了「学生写一段长文把判分提示套出来」。

学生产出永不入库

索引接口入参只有 doc_id 与原文。学生自己写的「标准答案」进不了检索库，也就污染不了后续会话。

下发字段白名单

发给学生的包只含：题号、语言、题面、埋雷版代码、轮次、证据片段。没有原版、diff、判级提示、期望等级、锚点。单测用键名白名单 + 禁词双断言守着。

证据结算前不回显

证据原文在结算前一个字都不回显给学生端，只能看到片段提示；完整引文在结算后随判级一起给出。

会话单向

结算后再 submit 一律 409。不能靠「再答一次刷新判分」。

越域即丢弃

模型返回闭集外的标签，条目直接丢弃并退回本地直判，不做「近似翻译」。

十 · 成本与性能

指标目标做法
在线调用硬上限 12 次 / 场9 + 1 + 1 + 1；提前收束留 3 次余量；冒烟实测 11 次
单场成本≤ 0.08 元预算守卫同时守次数与金额，任一超限即拒
题库命中0 次调用按内容指纹复用整题；跨会话证据 id 失效时本地重绑，不重新出题
结构记忆0 次调用同型题的历史轮次与追问角度直接查表，只给结构与话术，不含针对本次作答的推断
引用核验0 次调用本地比对 id 集合算 precision / recall
RAG 查询缓存默认 TTL 300 秒按服务、密钥指纹、查询和知识库隔离；空结果不缓存，避免错误结果长期污染
RAG 参考字符按题目封顶只把重排后选中的参考送入 Agent，并在报告中记录实际字符数，防止“检索了但没有用到”
离线出题埋雷不占在线预算出题、埋雷、探针全在离线完成；出错还被下一层兜住

所有速度优化都落在调用位置上（题库缓存、结构记忆、提前收束、深度 1 预取、按难度伸缩轮次），一个都不在模型层——因为模型是闭源 API，能改的只有调用次数。

十一 · 可观测与验收

健康检查

自动验收

项当前结果覆盖内容

联调三断言

  1. reserve 缺 stage 字段 → 409（不能 200 + 静默补默认值）
  2. 用 A 会话凭证检索 B 会话 / 锚点外库 → 403（不能返回空结果糊弄）
  3. judgment 引用的 evidence_id 不在封印集 → 422（不能照单全收）

十二 · 接口一览

方法路径说明
GET/v1/health版本、档位、预算上限、探针、检索是否降级
POST/v1/sessions开局，返回三道题（只有埋雷版）
GET/v1/sessions/{id}读进度，不花钱
POST/v1/sessions/{id}/submit提交一轮作答；带 Accept: text/event-stream 走 SSE 流式
POST/v1/sessions/{id}/settle结算，产出判级、引用核验、复盘与 rag_usage 使用概览
POST/v1/retrieve预留的检索代理（读方向）
GET/v1/evidence/{id}按证据编号取回片段

Web 层只守三件事：下发包是白名单字段、证据原文结算前不回显、会话单向。领域错误带状态码（404 / 409 / 422 / 502），壳里不出现 500 兜底。状态机只依赖标准库，不装 Web 框架也能测。

学生网页

以上接口之上配了一套学生网页（React + Vite，源码在 frontend/）：登录、训练工作台（三栏可调宽，AI 出题与对抗追问逐字输出）、报告、历史、能力分析、系统状态六个页面。部署时在容器内构建，由后端同源托管，页面直接请求 /v1/*，不产生跨域；本机改界面用 npm run dev 连 8010，只看演示数据用 npm run dev:mock。

十四 · 不做的事

  • 不做运行时建图与去中心化路由。本项目的价值在「口径锁定」，不在拓扑搜索；动态建图会让责任链断掉。
  • 不做 KV 级通信。模型是闭源 API，拿不到 KV，这条路线在工程上不成立。
  • 不做在线查询改写与多跳检索。一次改写就要再发一次请求，12 次预算扛不住三次。
  • 不做投机预跑。命中率不足，一半算力白烧，还会让预算账变得不可预测。
  • 不做「部分正确」这种中间标签。闭集只有命中与未命中；拿不准用置信度表达，不用新标签表达。

十五 · 风险与对策

风险表现对策
雷埋歪了原版也挂，或埋完跑不起来 探针在封印前复核「原版通过、埋雷版失败」；不通过整题剔除并计数
学生套话用长文本诱导判分提示或答案 决策档只吃结构化表；对抗方系统提示明确禁止给答案与位置
误判冤枉学生把「没看出来」判成「误报」 L0 只由读原文的升级层给；闭表从 L1 起步
对抗与裁判同源复核等于自己查自己 对抗独立档位；只配一家时健康检查如实报告 vendor_isolated: false
检索后端不可用会话开不了局 首次失败即降级本地桩；真实失败返回空，主链不断，并在 health 与 rag_usage 中显式标记
RAG 误召回把别的雷型或相似但无关的案例送给 Agent 显式雷型过滤 + 关键词/相似度本地重排；过滤数量进入统计，不能静默丢失
RAG 重复与空结果污染重复参考挤占上下文，或空结果被长期缓存 正文 SHA256 去重；空结果不缓存；缓存按知识库和密钥指纹隔离
RAG 只接通未生效配置显示已连接，但 Agent 实际没有使用参考 结算记录选中数、参考字符数和逐题支持数量；Reporter 直接展示实际使用证据
预算超支模型重试或链路加长 先查后花；提前收束留 3 次；成本与次数双闸

十六 · 一句话总结

这套系统的技术含量不在「用了几个 agent」，而在把每一个可能失守的地方都变成了结构约束：预算是异常不是日志，判分是闭集不是自由文本，证据是快照不是再检索，状态是单写者不是协商，误报是升级层的判断不是闭表的猜测，RAG 是按职责绑定并且可量化核验的参考层，不是一个无法追责的公共上下文。

学生带走的不该是「我答对了几道」，而是「我这次的判断停在了哪一级，下一步该练什么」。
