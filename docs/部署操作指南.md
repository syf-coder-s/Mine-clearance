# 部署操作指南（填 API、起服务）

写给要在新机器上把排雷兵跑起来的人。

## 第一步：装软件

只需要两个：

1. **Docker Desktop**：[https://www.docker.com/products/docker-desktop/](https://www.docker.com/products/docker-desktop/) 下载安装，装完打开一次，让它自己启动好（右下角图标变成绿色）。
2. **RAGFlow**：这是存"判例题库"的服务。如果别人已经部署好，跳过这步，只要拿到它的网址和密钥（见第二步）；如果自己装，按 RAGFlow 官方文档起容器即可。

## 第二步：填密钥（最重要的一步）

在项目根目录找到 `.env.example`，**复制一份，改名为 `.env`**（没有后缀），然后用记事本或 VS Code 打开 `.env`，填下面这些：

### 模型密钥（必填 3 个）

找模型厂商（如 MiMo、DeepSeek）的控制台创建 API Key，然后：

| 要填的行 | 填什么 | 去哪拿 |
|---|---|---|
| `LLM_API_BASE=` | 模型的接口网址 | 厂商文档里的 "API Base URL"，一般形如 `https://api.xxx.com/v1` |
| `LLM_API_KEY=` | 模型密钥 | 厂商控制台生成，形如 `sk-xxxx` |
| `REASONING_MODEL=` | 推理模型名字 | 如 `deepseek-v4-pro`（按厂商给的型号名填） |
| `DECISION_MODEL=` | 便宜的小模型名字 | 如 `deepseek-v4-flash` |
| `BUILDER_API_BASE=` / `BUILDER_API_KEY=` / `BUILDER_MODEL=` | 出题模型的网址/密钥/型号 | 同上，可以用同一家 |
| `ADVERSARY_API_BASE=` / `ADVERSARY_API_KEY=` / `ADVERSARY_MODEL=` | 对抗模型的网址/密钥/型号 | **必须换成另一家厂商**，不能和上面同一个模型（自己考自己等于没考） |

### RAGFlow 密钥（接了题库才需要填）

| 要填的行 | 填什么 | 去哪拿 |
|---|---|---|
| `RAG_PROVIDER=` | 改成 `ragflow` | 手动改 |
| `RAGFLOW_BASE_URL=` | RAGFlow 的网址 | 自己装的填 `http://localhost`；Docker 里访问本机 RAGFlow 填 `http://ragflow-gpu`（服务名不同就改成实际的） |
| `RAGFLOW_API_KEY=` | RAGFlow 密钥 | 打开 RAGFlow 网页 → 右上角头像 → API → 新建 API Key |
| `RAGFLOW_DATASET_ID=` | 判例库的 ID | 打开 RAGFlow 网页 → 进入判例知识库 → 看浏览器地址栏，`/datasets/` 后面那串就是 |
| `RAGFLOW_PATTERN_DATASET_ID=` | 缺陷模式库 ID | 同上方法，填模式库的 |
| `RAGFLOW_NEGATIVE_DATASET_ID=` | 反例库 ID | 同上方法，填反例库的 |

### 内部令牌（必填 1 个）

| 要填的行 | 填什么 |
|---|---|
| `MC_INTERNAL_TOKEN=` | 随便编一串长密码，如 `mc-token-8f3k2x...`，只给自己人建库用 |

其他行保持默认，**不要动**（预算上限、轮次这些都是冻结的规则）。

## 第三步：启动

打开 PowerShell，进入解压出来的 `Mine-clearance-main` 目录（就是有 `start.ps1` 的那一层）：

```powershell
Set-Location -LiteralPath '你的路径\Mine-clearance-main'
.\start.ps1
```

看到几行网址就是起好了。

## 第四步：检查有没有成功

浏览器打开 [http://localhost:8010/v1/health](http://localhost:8010/v1/health)，看三点：

1. 能打开页面 → 后端活着
2. `mock_llm` 是 `false` → 用的是真模型
3. `vendor_isolated` 是 `true` → 对抗方确实换了厂商

如果打不开：先确认 Docker Desktop 已启动，再跑 `docker compose logs --tail 50 api` 看报错，最常见原因是密钥填错或没填。

## 演示前最后确认（30 秒）

1. 打开学生网页登录后，看**右上角状态徽章**：
   - 绿色「在线 · v…」→ 一切正常
   - 黄色「模型未接入」→ 后端在用内置假数据，说明 `.env` 里模型密钥没填或填错，**别开始演示**
   - 红色「后端不可达」→ 后端没起来
2. 点「开始训练」后按钮会显示「AI 出题中，约需 1 分钟…」——这是正常的，真实模型出题就是要等，**不要刷新、不要重复点**。

## 常见问题

**`docker compose` 报错 `network docker_ragflow not found`**
说明这台机器上 RAGFlow 的 Docker 网络名不一样。运行 `docker network ls` 找到 RAGFlow 相关的网络名（通常带 ragflow 字样），然后在 `.env` 里加一行 `RAGFLOW_DOCKER_NETWORK=找到的名字`，再重新 `.\start.ps1`。

**起得来但网页右上角显示「模型未接入」**
`.env` 里 `LLM_API_KEY` / `BUILDER_API_KEY` / `ADVERSARY_API_KEY` 有没填或填错的，改完后运行 `docker compose up -d --force-recreate` 让新配置生效。

**RAGFlow 网页能打开，但排雷兵连不上题库**
确认 `.env` 里 `RAGFLOW_BASE_URL` 填的是 `http://ragflow-gpu`（不是 localhost——容器里 localhost 指它自己）。如果 RAGFlow 的容器服务名不叫 `ragflow-gpu`，改成实际名字。

## 平时怎么用

- 学生网页：[http://localhost:8010/](http://localhost:8010/)，账号密码都是 `123456`
- 停止服务：项目目录里运行 `.\stop.ps1`
- 下次再用：先开 Docker Desktop 和 RAGFlow，再 `.\start.ps1`

## 两个千万不要

1. **不要**运行 `docker compose down -v`——会删掉判例证据存档，删了找不回来。
2. **不要**把 `.env` 发给任何人或提交到网上——里面有全部密钥。
